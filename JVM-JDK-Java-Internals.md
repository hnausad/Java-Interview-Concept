# JVM, JDK & Java Internals — Detailed Interview Guide

---

# 1. Difference between JVM, JRE, and JDK

| Component | Meaning                  | Purpose                          |
| --------- | ------------------------ | -------------------------------- |
| JVM       | Java Virtual Machine     | Runs Java bytecode               |
| JRE       | Java Runtime Environment | JVM + libraries to run Java apps |
| JDK       | Java Development Kit     | JRE + development tools          |

---

## Diagram

```text
JDK
 ├── JRE
 │    ├── JVM
 │    └── Java Libraries
 └── Development Tools
```

---

## Example

### Compile

```bash
javac Test.java
```

Uses:

* JDK
* Compiler

### Run

```bash
java Test
```

Uses:

* JRE
* JVM

---

# 2. Explain JVM Architecture in Detail

## JVM Flow

```text
.java file
   ↓
javac compiler
   ↓
.class bytecode
   ↓
ClassLoader
   ↓
Runtime Memory Areas
   ↓
Execution Engine
   ↓
Native OS
```

---

# JVM Components

## A. ClassLoader

Loads `.class` files into memory.

### Phases

1. Loading
2. Linking
3. Initialization

---

## B. Runtime Data Areas

### Heap

Stores objects.

### Stack

Stores method calls and local variables.

### Metaspace

Stores class metadata.

### PC Register

Stores current instruction.

### Native Method Stack

For native methods.

---

## C. Execution Engine

Executes bytecode.

Components:

* Interpreter
* JIT Compiler
* Garbage Collector

---

## Example

```java
class Test {
    public static void main(String[] args) {
        Student s = new Student();
    }
}
```

### What Happens?

* ClassLoader loads `Test.class`
* JVM creates stack frame for `main()`
* Object created in Heap
* Reference stored in Stack

# 3. What are Heap, Stack, and Metaspace?

---

# Heap Memory

Stores:

* Objects
* Instance variables

Shared among threads.

## Example

```java
Student s = new Student();
```

`Student` object stored in Heap.

---

# Stack Memory

Stores:

* Local variables
* Method calls

Thread-specific.

## Example

```java
public void test() {
    int x = 10;
}
```

`x` stored in Stack.

---

# Metaspace

Stores:

* Class metadata
* Method metadata

Introduced in Java 8.

---

# Memory Diagram

```text
Heap
 ├── Objects
 └── Arrays

Stack
 ├── Method Calls
 └── Local Variables

Metaspace
 └── Class Information
```

# 4. How does Java achieve platform independence?

Java uses:

* Bytecode
* JVM

---

## Flow

```text
Java Code
   ↓
Bytecode
   ↓
JVM converts to machine code
```

Different OS has different JVM.

---

## Example

Same `.class` file runs on:

* Windows
* Linux
* Mac

Because JVM handles OS-specific execution.

# 5. What is Bytecode in Java?

Intermediate code generated by compiler.

Stored in:

```text
.class file
```

---

## Example

```java
System.out.println("Hello");
```

Converted to bytecode.

View using:

```bash
javap -c Test.class
```

# 6. How does JIT Compiler work?

JIT = Just In Time Compiler

Converts frequently used bytecode into native machine code.

---

# Without JIT

```text
Bytecode → Interpreter → Slow
```

# With JIT

```text
Frequently used code
      ↓
Compiled to machine code
      ↓
Faster execution
```

---

## Example

Loop executed millions of times gets optimized.

```java
for(int i=0;i<1000000;i++) {
    sum += i;
}
```

JIT compiles loop to native code.

---

# 7. How does Garbage Collection work?

GC removes unused objects.

---

## Example

```java
Student s = new Student();
s = null;
```

Object becomes eligible for GC.

---

# GC Process

## Mark

Find unused objects.

## Sweep

Remove objects.

## Compact

Defragment memory.

---

# 8. Difference between G1GC, ZGC, and Serial GC

| GC        | Best For          | Pause Time |
| --------- | ----------------- | ---------- |
| Serial GC | Small apps        | High       |
| G1GC      | Large heaps       | Medium     |
| ZGC       | Ultra-low latency | Very low   |

---

# Serial GC

Single thread GC.

```bash
-XX:+UseSerialGC
```

---

# G1GC

Heap divided into regions.

```bash
-XX:+UseG1GC
```

Default in modern Java.

---

# ZGC

Ultra-low pause GC.

```bash
-XX:+UseZGC
```

Pause usually < 10ms.

---

# 9. What causes memory leaks in Java?

Objects not garbage collected.

---

# Common Causes

## Static Collections

```java
static List list = new ArrayList();
```

Objects remain forever.

---

## Unclosed Resources

```java
Connection con = DriverManager.getConnection();
```

Not closing connection causes leak.

---

## Listener Leaks

Event listeners not removed.

# 18. What are strong, weak, and soft references?

---

# Strong Reference

Default reference.

```java
Student s = new Student();
```

GC will NOT remove object.

---

# Weak Reference

GC removes object aggressively.

```java
WeakReference<Student> ref
```

Used in:

* WeakHashMap

---

# Soft Reference

Removed only when memory low.

Used in:

* Caching

---

# Example

```java
SoftReference<byte[]> cache
```

# 20. Difference between StackOverflowError and OutOfMemoryError

| StackOverflowError | OutOfMemoryError    |
| ------------------ | ------------------- |
| Stack full         | Heap/Metaspace full |
| Deep recursion     | Too many objects    |
| Method calls issue | Memory exhaustion   |

---

# StackOverflow Example

```java
public void test() {
    test();
}
```

Infinite recursion.

---

# OutOfMemory Example

```java
List list = new ArrayList();

while(true) {
    list.add(new byte[1024*1024]);
}
```

Heap exhausted.

* Better performance
* Lower memory usage
* Faster response time
* Reduced GC pauses

# Why JVM Tuning is Needed?

Default JVM settings may not be ideal for:

* High traffic systems
* Large heap applications
* Microservices
* Trading systems
* Banking applications

# Main Areas of JVM Tuning

| Area         | Purpose                 |
| ------------ | ----------------------- |

| Thread Stack | Prevent stack overflow  |

# 2. GC Tuning

GC tuning means optimizing garbage collection.

Goal:

* Reduce pause time
* Improve throughput
* Prevent Full GC

---

# Key GC Concepts

---

# Minor GC

Cleans Young Generation.

Fast.

---

# Major GC

Cleans Old Generation.

Slow.

---

# Full GC

Cleans entire heap.

Very expensive.

---

# Important GC Algorithms

| GC          | Best For          |
| ----------- | ----------------- |
| Serial GC   | Small apps        |
| Parallel GC | High throughput   |
| G1GC        | Balanced systems  |
| ZGC         | Ultra low latency |
| Shenandoah  | Low pause systems |

---

# G1GC

Default modern GC.

```bash id="1adrcq"
-XX:+UseG1GC
```

Good for:

* Large heaps
* Microservices

---

# ZGC

Ultra-low pause collector.

```bash id="qzslbe"
-XX:+UseZGC
```

Pause usually:

```text id="b5h69n"
< 10ms
```

---

# Important GC Tuning Parameters

---

# Max Pause Goal

```bash id="y5p1to"
-XX:MaxGCPauseMillis=200
```

---

# Heap Occupancy

```bash id="r8zvqo"
-XX:InitiatingHeapOccupancyPercent=45
```

---

# GC Threads

```bash id="m57b1j"
-XX:ParallelGCThreads=8
```

---

# GC Tuning Example

```bash id="w8e3yj"
java -Xms4g -Xmx4g \
     -XX:+UseG1GC \
     -XX:MaxGCPauseMillis=100
```

Thread dump shows:

* All JVM threads
* Their states
* Stack traces

Used for:

* Deadlock analysis
* Performance issues
* High CPU debugging

---

# Generate Thread Dump

```bash id="ohsyc4"

```

---

# Thread States

| State         | Meaning              |
| ------------- | -------------------- |
| RUNNABLE      | Executing            |
| BLOCKED       | Waiting for lock     |
| WAITING       | Waiting indefinitely |
| TIMED_WAITING | Sleeping/waiting     |
| TERMINATED    | Finished             |

---

# Example Deadlock

```java id="jtzkvg"
Thread1 locks A → waits B
Thread2 locks B → waits A
```

Thread dump shows:

```text id="y4njlwm"

```

---

# Important Things to Analyze

---

# BLOCKED Threads

Indicates lock contention.

---

# High CPU Threads

Usually infinite loops.

---

# Deadlocks

Two threads waiting forever.

---

# Waiting Threads

May indicate external dependency issues.

---

# 5. ClassLoader Leaks

One of the most advanced JVM problems.

---

# What is a ClassLoader Leak?

Classes cannot unload because:

* ClassLoader still referenced

Result:

* Metaspace grows forever

---

# Common in

* Apache Tomcat
* JBoss
* Hot deployments
* Plugin systems

---

# Example

```java id="dbs26x"
static Object obj;
```

If object references application class:

* Old ClassLoader cannot unload

---

# Symptoms

* Increasing Metaspace
* Full GC frequency
* `OutOfMemoryError: Metaspace`

---

# Detection Tools

* MAT
* JProfiler
* VisualVM

---

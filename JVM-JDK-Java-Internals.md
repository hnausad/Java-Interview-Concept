# JVM, JDK & Java Internals — Detailed Interview Guide

---

# 1. Difference between JVM, JRE, and JDK

| Component | Meaning                  | Purpose                          |
| --------- | ------------------------ | -------------------------------- |
| JVM       | Java Virtual Machine     | Runs Java bytecode               |
| JRE       | Java Runtime Environment | JVM + libraries to run Java apps |
| JDK       | Java Development Kit     | JRE + development tools          |

---

## Diagram

```text
JDK
 ├── JRE
 │    ├── JVM
 │    └── Java Libraries
 └── Development Tools
```

---

## Example

### Compile

```bash
javac Test.java
```

Uses:

* JDK
* Compiler

### Run

```bash
java Test
```

Uses:

* JRE
* JVM

---

# 2. Explain JVM Architecture in Detail

## JVM Flow

```text
.java file
   ↓
javac compiler
   ↓
.class bytecode
   ↓
ClassLoader
   ↓
Runtime Memory Areas
   ↓
Execution Engine
   ↓
Native OS
```

---

# JVM Components

## A. ClassLoader

Loads `.class` files into memory.

### Phases

1. Loading
2. Linking
3. Initialization

---

## B. Runtime Data Areas

### Heap

Stores objects.

### Stack

Stores method calls and local variables.

### Metaspace

Stores class metadata.

### PC Register

Stores current instruction.

### Native Method Stack

For native methods.

---

## C. Execution Engine

Executes bytecode.

Components:

* Interpreter
* JIT Compiler
* Garbage Collector

---

## Example

```java
class Test {
    public static void main(String[] args) {
        Student s = new Student();
    }
}
```

### What Happens?

* ClassLoader loads `Test.class`
* JVM creates stack frame for `main()`
* Object created in Heap
* Reference stored in Stack

# 3. What are Heap, Stack, and Metaspace?

---

# Heap Memory

Stores:

* Objects
* Instance variables

Shared among threads.

## Example

```java
Student s = new Student();
```

`Student` object stored in Heap.

---

# Stack Memory

Stores:

* Local variables
* Method calls

Thread-specific.

## Example

```java
public void test() {
    int x = 10;
}
```

`x` stored in Stack.

---

# Metaspace

Stores:

* Class metadata
* Method metadata

Introduced in Java 8.

---

# Memory Diagram

```text
Heap
 ├── Objects
 └── Arrays

Stack
 ├── Method Calls
 └── Local Variables

Metaspace
 └── Class Information
```

Java uses:

* Bytecode
* JVM

---

## Flow

```text

   ↓

   ↓
```

Intermediate code generated by compiler.

Stored in:

```text
.class file
```

---

```java
System.out.println("Hello");
```

Converted to bytecode.

View using:


# 6. How does JIT Compiler work?

JIT = Just In Time Compiler

Converts frequently used bytecode into native machine code.

---

# Without JIT

```text
Bytecode → Interpreter → Slow
```

# With JIT

```text
Frequently used code
      ↓
Compiled to machine code
      ↓
Faster execution
```

---

## Example

Loop executed millions of times gets optimized.

```java
for(int i=0;i<1000000;i++) {
    sum += i;
}
```

JIT compiles loop to native code.

---

# 7. How does Garbage Collection work?

GC removes unused objects.

---

## Example

```java
Student s = new Student();
s = null;
```

Object becomes eligible for GC.

---

# GC Process

## Mark

Find unused objects.

## Sweep

Remove objects.

## Compact

Defragment memory.

---

# 8. Difference between G1GC, ZGC, and Serial GC

| GC        | Best For          | Pause Time |
| --------- | ----------------- | ---------- |
| Serial GC | Small apps        | High       |
| G1GC      | Large heaps       | Medium     |
| ZGC       | Ultra-low latency | Very low   |

---

# Serial GC

Single thread GC.

```bash
-XX:+UseSerialGC
```

---

# G1GC

Heap divided into regions.

```bash
-XX:+UseG1GC
```

Default in modern Java.

---

# ZGC

Ultra-low pause GC.

```bash
-XX:+UseZGC
```

Pause usually < 10ms.

---

# 9. What causes memory leaks in Java?

Objects not garbage collected.

---

# Common Causes

## Static Collections

```java
static List list = new ArrayList();
```

Objects remain forever.

---

## Unclosed Resources

```java
Connection con = DriverManager.getConnection();
```

Not closing connection causes leak.

---

## Listener Leaks

Event listeners not removed.

# 15. What is Escape Analysis in JVM?

JVM optimization technique.

Checks whether object escapes method/thread.

---

# Example

```java
public void test() {
    User u = new User();
}
```

If object doesn't escape:

* JVM may allocate on stack
* Avoid heap allocation

---

# Benefits

* Faster execution
* Reduced GC pressure

# 18. What are strong, weak, and soft references?

---

# Strong Reference

Default reference.

```java
Student s = new Student();
```

GC will NOT remove object.

---

# Weak Reference

GC removes object aggressively.

```java
WeakReference<Student> ref
```

Used in:

* WeakHashMap

---

# Soft Reference

Removed only when memory low.

Used in:

* Caching

---

# Example

```java
SoftReference<byte[]> cache
```

# 20. Difference between StackOverflowError and OutOfMemoryError

| StackOverflowError | OutOfMemoryError    |
| ------------------ | ------------------- |
| Stack full         | Heap/Metaspace full |
| Deep recursion     | Too many objects    |
| Method calls issue | Memory exhaustion   |

---

# StackOverflow Example

```java
public void test() {
    test();
}
```

Infinite recursion.

---

# OutOfMemory Example

```java
List list = new ArrayList();

while(true) {
    list.add(new byte[1024*1024]);
}
```

Heap exhausted.
